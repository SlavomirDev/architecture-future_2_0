# Roadmap трансформации «Будущее 2.0»

## Общая логика

Трансформация разбита на этапы:
- сначала убираются ключевые ограничения (DWH, связность);
- затем строится платформа данных;
- после этого включается self-service аналитика и развитие доменов.

Каждый этап даёт отдельный бизнес-результат.

## Этап 1. Подготовка и декомпозиция (0–2 месяца)

**Цель:**
Зафиксировать архитектуру и подготовить систему к изменениям.

**Основные шаги:**
- Выделение доменов (Healthcare, FinTech, AI)
- Определение границ данных
- Проектирование Data Platform
- Подготовка облачной инфраструктуры

**Результат:**
- Понятная архитектура
- Зафиксированные зоны ответственности
- Готовность к масштабированию

**Команды:**
- Архитекторы
- Data Engineers
- DevOps

**Ресурсы:**
- Облачная инфраструктура
- Время на аудит систем

**Зачем это нужно:**
Без этого этапа любые изменения будут хаотичными.  
Он снижает риски и задаёт основу для всех последующих шагов.

## Этап 2. Интеграционный слой и события (2–5 месяцев)

**Цель:**
Снизить связность систем и подготовить основу для масштабирования.

**Основные шаги:**
- Внедрение Kafka как шины событий
- Перевод ключевых систем на публикацию событий
- Введение API Gateway

**Результат:**
- Слабая связность между системами
- Возможность подключать новые сервисы без изменений в ядре

**Команды:**
- Backend команды доменов
- Platform команда

**Ресурсы:**
- Kafka кластер
- API Gateway

**Зачем это нужно:**
Позволяет подключать новые бизнес-направления (фарма, устройства) без переделки всей системы.

## Этап 3. Data Platform (Lakehouse) (4–8 месяцев)

**Цель:**
Убрать нагрузку с DWH и ускорить аналитику.

**Основные шаги:**
- Внедрение Data Lake (raw слой)
- Построение DWH нового поколения (curated слой)
- Настройка пайплайнов загрузки данных

**Результат:**
- Централизованная платформа данных
- Снижение нагрузки на операционные системы
- Быстрая обработка данных

**Команды:**
- Data Engineers
- Platform команда

**Ресурсы:**
- S3-хранилище
- DWH (ClickHouse / BigQuery)
- ETL/ELT инструменты

**Зачем это нужно:**
Решает главную проблему — медленную отчётность.  
Данные начинают обрабатываться быстрее и в нужной структуре.

## Этап 4. Semantic Layer и BI портал (6–10 месяцев)

**Цель:**
Дать бизнесу доступ к данным без участия IT.

**Основные шаги:**
- Внедрение semantic layer (dbt)
- Создание витрин данных
- Развёртывание BI портала

**Результат:**
- Self-service аналитика
- Быстрое построение отчётов
- Снижение нагрузки на команды разработки

**Команды:**
- Data Analysts
- BI команда

**Ресурсы:**
- BI инструмент (Power BI / DataLens)
- dbt

**Зачем это нужно:**
Позволяет бизнесу самостоятельно работать с данными и быстрее принимать решения.

## Этап 5. Развитие AI и real-time (8–12 месяцев)

**Цель:**
Улучшить качество сервисов и ускорить реакции системы.

**Основные шаги:**
- Внедрение Feature Store
- Подключение ML моделей к Data Platform
- Использование потоковых данных

**Результат:**
- Быстрая работа моделей
- Улучшение качества медицинских и финансовых сервисов

**Команды:**
- ML Engineers
- Data Engineers

**Ресурсы:**
- Feature Store
- ML инфраструктура

**Зачем это нужно:**
Позволяет использовать данные не только для отчётов, но и для улучшения сервисов в реальном времени.

## Этап 6. Управление данными и безопасность (параллельно)

**Цель:**
Обеспечить соответствие требованиям и защиту данных.

**Основные шаги:**
- Введение Data Catalog
- Настройка прав доступа
- Контроль происхождения данных

**Результат:**
- Прозрачность данных
- Соответствие требованиям (медицина, финансы)

**Команды:**
- Data Governance
- Security

**Ресурсы:**
- Инструменты каталогизации
- IAM решения

**Зачем это нужно:**
Без этого нельзя безопасно масштабировать систему и открывать доступ к данным.
