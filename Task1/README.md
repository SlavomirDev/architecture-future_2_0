# Анализ проблемных мест и их приоритизация

| Приоритет (Матрица Эйзенхауэра) | Проблемная область | Конкретная проблема | Влияние на бизнес-сценарии | Бизнес-последствия |
| :--- | :--- | :--- | :--- | :--- |
| **Критично (Важно & Срочно)** | **Монолитный DWH** | Централизация всех данных и бизнес-логики в одном хранилище (SQL Server 2008). | **Быстрая отчетность** | Отчёты формируются часами → задержки управленческих решений. |
| | **Отсутствие доменной декомпозиции** | Медицинские, финансовые и AI-данные смешаны. | **Независимое развитие** | Любые изменения затрагивают весь ландшафт → рост стоимости. |
| | **ESB как монолит** | Apache Camel содержит всю логику маршрутизации, трансформации, оркестрации. | **Интеграция новых бизнесов** | Сложно подключать партнёров. |
| **Высокий** | **Отсутствие Data Lakehouse** | Нет разделения на raw / curated / semantic слои. | **Self-service аналитика** | Дублирование логики. |
| | **Отсутствие Data Governance** | Нет каталога данных, контроля доступа. | **Безопасность** | Риски утечек мед. и фин. данных. |
| | **Устаревшие технологии** | PowerBuilder, SQL Server 2008, ESB | **Надёжность** | Высокая стоимость поддержки. |

## Целевая архитектура: совокупность компонентов по доменам

### Домены и их компоненты
| Домен | Компоненты | Назначение |
| :--- | :--- | :--- |
| **Головная компания** | Сопровождающие системы, 1С, БД учета, Legacy ESB, Central Kafka, Data Lakehouse | Консолидация, аналитика, отчётность |
| **Клиники** | МИС, Healthcare DB, Healthcare S3, Kafka Медицины | Медицинские данные, пациенты, исследования |
| **Финтех** | Core Banking System, FinTech DB, Финтех-сервисы, Kafka Финтех | Банковские операции, кредиты, платежи |
| **ИИ-сервисы** | ИИ-сервисы, Личный кабинет ИИ, AI Result DB, Kafka ИИ | Диагностика, обработка изображений |

### Интеграционная стратегия: Kafka как backbone
Вместо единого ESB внедряется **децентрализованная событийная архитектура**:

| Компонент | Роль |
| :--- | :--- |
| **Доменные Kafka** (Медицина, Финтех, ИИ) | Каждый домен публикует события в локальную Kafka |
| **Central Kafka** | Центральная платформа, агрегирующая данные из всех доменов |
| **MirrorMaker** | Синхронизация топиков между доменами и центром |
| **Legacy ESB** | Остаётся для обратной совместимости, постепенно вытесняется |

## Итог: ключевые проблемы для бизнеса

1. **DWH перегружен** — отчёты строятся часами
2. **Нет разделения на домены** — изменения дорогие
3. **ESB — монолит** — вся логика завязана на одной шине

---

## Приоритет действий

**Первая очередь:**
- Разделить систему на домены
- Развернуть доменные Kafka и Central Kafka
- Настроить CDC (Debezium) из БД в Kafka
- Построить Data Lakehouse (S3 + ClickHouse + Iceberg)
- Реализовать API слой

**Вторая очередь:**
- Перенести аналитику с DWH на Data Lakehouse
- Внедрить портал самообслуживания
- Настроить Data Governance
- Вытеснять ESB, переводить интеграции на Kafka

**Третья очередь:**
- Полное отключение Legacy ESB
- Развитие ИИ-инфраструктуры
- API Gateway для партнёров

## Вывод
Основная проблема — в **централизации**. Сейчас всё завязано на DWH и ESB.

**Целевая архитектура решает это через совокупность компонентов:**
1. **Доменная декомпозиция**
3. **Data Lakehouse**
4. **Постепенное вытеснение ESB**
