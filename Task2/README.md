# Обоснование разделения на домены

## Выделенные домены

В целевой архитектуре система разделена на следующие домены:

1. Healthcare Domain (медицина)
2. FinTech Domain (финансовые сервисы)
3. AI Domain (сервисы машинного обучения)
4. Data Platform Domain (аналитика и витрины данных)
5. Integration Domain (интеграции и обмен данными)

Такое разделение соответствует ключевым бизнес-направлениям компании и позволяет развивать их независимо.

## Логика разделения

### 1. Healthcare
Отвечает за:
- медицинские процессы;
- хранение медицинских данных;
- работу врачей.

Особенность:
- содержит чувствительные данные (медкарты, исследования);
- не участвует напрямую в аналитике (по условиям кейса).

Польза:
- можно изолировать медицинские данные;
- проще соблюдать требования регуляторов;
- изменения не влияют на другие домены.

### 2. Финтех
Отвечает за:
- банковские операции;
- счета, кредиты, транзакции.

Польза:
- независимое развитие финансовых продуктов;
- возможность быстрого добавления новых сервисов (например, кредитование, страхование);
- изоляция финансовых рисков.

### 3. AI
Отвечает за:
- обучение и использование моделей;
- обработку данных для прогнозов и рекомендаций.

Польза:
- модели можно развивать независимо от остальных систем;
- упрощается внедрение новых AI-сценариев;
- нет необходимости менять DWH при добавлении моделей.

### 4. Data Platform
Отвечает за:
- хранение и обработку данных для аналитики;
- формирование витрин;
- предоставление данных пользователям.

Особенность:
- не содержит бизнес-логики доменов;
- агрегирует данные из всех источников.

Польза:
- снимает нагрузку с операционных систем;
- ускоряет построение отчётов;
- позволяет реализовать self-service аналитику.

### 5. Integration
Отвечает за:
- обмен данными между доменами;
- интеграцию с внешними системами;
- потоковую передачу данных.

Польза:
- слабая связность между доменами;
- упрощение подключения новых партнёров;
- переход к событийной архитектуре.

## Потоки данных между доменами

### Основной принцип
Домены не обращаются друг к другу напрямую через базы данных.  
Обмен происходит через:
- события (Kafka);
- API.

### Сценарий 1: Построение отчёта
1. Данные из Healthcare и FinTech публикуются в виде событий.
2. События поступают в Data Platform.
3. Данные обрабатываются и попадают в витрины.
4. Пользователь получает отчёт через BI.

Результат:
- отчёты формируются быстрее;
- нет нагрузки на операционные системы.

## Преимущества для бизнеса
1. Ускорение вывода продуктов  
   Новые сервисы можно запускать внутри отдельного домена, не затрагивая всю систему.
2. Снижение зависимости от DWH  
   DWH больше не является центром всей логики. Он используется только для аналитики.
3. Независимое развитие направлений  
   Медицина, финтех и AI могут развиваться параллельно без конфликтов.
4. Упрощение интеграций  
   Новые партнёры подключаются через API и события, без сложных доработок.
5. Повышение масштабируемости  
   Каждый домен можно масштабировать отдельно в зависимости от нагрузки.

## Вывод
Разделение на домены позволяет уйти от текущей централизованной модели, где всё зависит от одного DWH.
Система становится более гибкой: каждое направление развивается отдельно, а данные связываются через понятные и контролируемые механизмы.
Это напрямую поддерживает цели бизнеса — быстрее запускать новые продукты, работать с данными без задержек и подключать новые направления без полной перестройки системы.
